# TinkerBlink

Mobile app (Android + web, iOS untested) for self-hosted Blynk Legacy servers (blynk-server 0.41.x).
Overview, build and license: [README.md](README.md). Protocol: [docs/protocol.md](docs/protocol.md). Widget values and
layout: [docs/widgets.md](docs/widgets.md). Personal, unversioned notes may live in `CLAUDE.local.md`.

## Layout

```
app/                    Expo SDK 57 + React Native 0.86 + TypeScript (package app.tinkerblink, scheme tinkerblink://)
                        Has its own app/AGENTS.md (Expo template): versioned Expo docs, `npx expo install`.
  src/app/              Expo Router routes: index (login), projects, dashboard/[id], edit/… (widget settings),
                        project/new, project/[dashId] (settings), project/[dashId]/device/[deviceId], credits
  src/session/          SessionManager (connection, pause in background, reconnection), LiveStore (pin values,
                        setProperty, device status), credentials (SecureStore; on web the password is never stored),
                        connectionError (plain-words connection errors)
  modules/tinkerblink-tls  "Trust this certificate" (Android): SHA-256 of the server certificate per host:port, checked
                        only after the system check fails; screen src/app/certificate.tsx, opened from the login
                        (certificate button colored by useCertificateLevel, link after a failed login), never from a
                        deep link URL: the server comes from the session (selectCertificateHost)
  src/model/profile.ts  profile types and pin keys ("<dash>-<dev>-v<pin>")
  src/components/       DashboardGrid (8-column grid, cell height 1.35 x width, tabs row hidden), scrollLock
  src/layout/           bandLayout: wide screens show row bands side by side (pure function, data unchanged)
  src/widgets/          widget components (WidgetView picks by type), color.ts, format.ts, superchart/, map/
  src/editor/           dashboard editor: policy (editable = own projects, never assigned ones), fields, PinPicker
                        + boards/ (MIT data from gablau/tinkerblink-boards), EditLayer + layoutRules, WidgetBox + catalog, widgetIcons,
                        widgetDocs (generated by app/scripts/import-widget-docs.js)
  src/project/          projects and devices (tokens: never log them). boardTypes.ts: the board list between
                        `// <boards>` markers is generated from the server BoardType enum; WI_FI_BOARDS is manual
  src/sensors/          phone sensors (local module modules/tinkerblink-sensors) and background GPS (gps.ts)
  src/ui/               themes (dashboardTheme.ts), palette, fonts (Barlow)
  src/i18n.ts           Italian/English texts following the phone language
  src/credits.ts        credits and licenses shown in /credits: update it when adding a library, font, service or
                        external data
  plugins/              config plugins: withNetworkSecurityConfig (user CAs + cleartext only in debug builds),
                        withShortCxxPath (Windows path length for the release C++ build), withAbiSplits (one APK
                        per ABI, only with -PtinkerblinkAbiSplits), withGradleTuning (Gradle memory + build cache)
  scripts/              render-icons.mjs (icon PNGs from assets/icon-src/tiles.mjs), build-release.js (`npm run
                        build:apk`: signed APKs per ABI + universal in dist/<version>/, not versioned; `npm run
                        build:aab`: Google Play bundle in the same folder) and sign-release.js,
                        import-widget-docs.js, import-boards.js (`node app/scripts/import-boards.js <tinkerblink-boards
                        clone> <blynk-server clone>`: pin maps, board index and the board list of boardTypes.ts)
protocol/               @tinkerblink/protocol (MIT): TypeScript client, portable Node/React Native (Uint8Array only,
                        @noble/hashes, fflate). `npm run selftest -w @tinkerblink/protocol`
patches/                patch-package patches (expo-video: RTSP + RTP over TCP)
```

## Commands

- `npm install` at the root (workspaces app + protocol; postinstall applies the patches).
- `npm run typecheck -w app`, `npm run lint -w app`, `npm run selftest -w @tinkerblink/protocol`.
- `cd app && npm run web` / `npx expo run:android` (development build; Expo Go is not enough).

## Notes

- `app/android` is generated by `npx expo prebuild --platform android --no-install` (CNG, not versioned): never edit
  it by hand. Run prebuild **inside app/**: from the root it creates a wrong android/ and app.json.
- Expo modules come as prebuilt AARs and ignore source patches: `app/package.json` has
  `expo.autolinking.android.buildFromSource = ["expo-video"]`. A new patched module must be added there too.
- After changing SessionManager/LiveStore classes, fast refresh keeps the old instances: restart the app.
- After adding native modules: prebuild + `npx expo run:android`, then Metro with `--clear`.
- On Windows, if prebuild fails with EBUSY on app/android, the VS Code Gradle extension is holding it open.
- The video URL may contain camera credentials and device tokens are secrets: never print them in logs.
- The protocol client is read-only by default (`readOnly: true`); writes must be enabled explicitly.
- Every app connection makes the server send `acon`/`adis` events to the devices of the account: keep test
  connections short.
